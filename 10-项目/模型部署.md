# 🚀 Qwen3.5-35B MoE 部署避坑实录

## 📌 背景
- **硬件**: NVIDIA RTX A6000 (48GB) x 2
- **模型**: Qwen3.5-35B-A3B (Safetensors)
- **目标**: 使用 vLLM 暴露 OpenAI 兼容 API 接口

---

## ❌ 遇到问题与解决 (Troubleshooting)

### 1. **vLLM V1 引擎（新版实验性引擎）** 特有的 **多进程同步超时**问题。
- **现象**: 报错 `No available shared memory broadcast block found in 60 seconds. This typically happens when some processes are hanging or doing some time-consuming work (e.g. compilation, weight/kv cachee quantizat.
- **原因**: 
	1. **同步机制**：主进程发出一个信号，所有子进程必须在 **60 秒** 内响应。
	2. **超时原因**：你的模型是 **Qwen 3.5 MoE（混合专家模型）**。这种模型结构非常复杂，拥有大量的专家权重。在初始化过程中，vLLM 需要进行 **Triton Kernel 预热（Warmup）**。
	3. **瓶颈**：对于 MoE 模型，预热上百个专家算子的时间往往会超过 60 秒。主进程等得“不耐烦”了，以为子进程挂掉了，于是抛出这个错误。
- **解决**: 
		1. 方案 A：增加同步超时阈值（最直接）：export VLLM_SHM_BROADCAST_TIMEOUT=600
		2. 方案 B：退回到 V0 稳定引擎（最稳妥）

### 2. 显存溢出 (OOM)
- **现象**: `CUDA out of memory. Tried to allocate 512 MiB`.
- **原因**: 35B 模型权重约 70GB，默认加载到单张卡（48GB）放不下。
- **解决**: 启用 **张量并行 (Tensor Parallel)**，设置 `--tensor-parallel-size 2`。

### 3. vLLM V1 引擎初始化卡死
- **现象**: 循环报错 `No available shared memory broadcast block found`.
- **原因**: V1 实验性引擎对 MoE 模型预热时间过长，触发共享内存同步超时（60s）。
- **解决**: 
    - 强制退回稳定版引擎: `export VLLM_USE_V1=0`
    - 禁用 CUDA Graph（MoE 结构复杂导致捕获极慢）: `--enforce-eager`
    - 禁用 P2P 通信优化: `export NCCL_P2P_DISABLE=1`

### 4. API 访问 404 (Proxy 拦截)
- **现象**: 服务已启动，但 `curl localhost:8000` 返回 `Not Found`。
- **原因**: 全局网络代理将 `localhost` 请求转发至外部代理服务器。
- **解决**: 设置本地不代理：`export no_proxy="localhost,127.0.0.1"`。

## ✅ 最终稳定启动方案

### 1. 环境变量配置
```bash
export VLLM_USE_V1=0
export NCCL_P2P_DISABLE=1
export NCCL_IB_DISABLE=1
export no_proxy="localhost,127.0.0.1"
```

### 2. 启动命令
```bash
# 建议在 tmux 会话中运行以防掉线
python -m vllm.entrypoints.openai.api_server \
    --model /home/e/models/Qwen3.5-35B-A3B \
    --trust-remote-code \
    --tensor-parallel-size 2 \
    --max-model-len 4096 \
    --gpu-memory-utilization 0.85 \
    --enforce-eager \
    --disable-custom-all-reduce \
    --host 0.0.0.0 \
    --port 8000
```
